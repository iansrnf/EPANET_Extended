5. DATA FIDELITY AND TOPOLOGY INVARIANTS

These details are important; do not "simplify" them away.

- Default connection tolerance is 0.1 meters.
- Ordinary interior pipe vertices preserve bends and do not automatically create junctions.
- Pure geometric crossings remain disconnected by default.
- Explicit intersection/vertex options can create those connections.
- Candidate nodes originate from network point records and pipe endpoints.
- Critically, an existing endpoint node with pipe incidence >=2 must not create additional on-pipe cuts by default. Explicit advanced options can override this.
- Missing this degree rule produced 350 rather than 348 pipes on the official Rosebery example.
- Preserve source bends, proper intermediate vertices, and length apportionment when splitting a stated pipe length.
- Synthetic string refs establish source topology; converters generate actual numeric model IDs and final unique labels.
- Link vertices are intermediate points only, not duplicated endpoints.

Point pumps/valves:
- Become short links, not node assets pretending to be devices.
- Target device length is one project length unit.
- Adjacent degree-one geometry is trimmed by the smaller of half a project unit or one-third the adjacent length.
- At exactly two incident pipes, transfer the second pipe to a duplicate junction.
- Preserve/inherit/interpolate elevations when creating or trimming nodes.
- Warn about isolated or ambiguous device connections.

Hydraulic values:
- Missing source hydraulics remain missing unless the user configured a valid default.
- Preserve a stated numeric zero.
- Preserve valid negative junction demands as injection sources.
- Elevation/head may legitimately be negative.
- Reject/report invalid numeric/enum values and use valid configured fallbacks or absence.
- Do not invent roughness, reservoir head, tank levels/dimensions, or elevations just to make simulation pass.
- Pipe/pump default status is open; the model's pump enum is normalized appropriately.
- Valve kind defaults to TCV. Without a mapped valid status, a numeric setting implies active; no setting implies open.
- Builder tanks allow overflow by default.
- Source Z elevations must be converted using source elevation units.
- Terrain fills ONLY missing node elevations. It must not replace supplied Z/mapped elevation or create a reservoir head.
- Reservoir mapped head is absolute and independent of terrain elevation.
- Tank levels are relative levels.

Customers/zones:
- Customer demand input is l/d for metric or gal/d for US, independent of the selected hydraulic flow unit.
- Do not interpret a daily customer quantity as l/s or gal/min.
- Customers remain unallocated and outside pipe topology after building.
- Their demands do not affect simulation until allocation/connection through the existing app workflow.
- Zone-label merging belongs to the existing converter builder.

7. CORE APIs AND LIFECYCLE

Source ingestion:
expandGisFiles(files, {signal?, maxExpandedBytes?}) -> SourceFile[]
groupGisFiles(files) -> {name, files}[]

Archive invariants:
- Default aggregate expanded-byte budget: 256 MiB.
- One nested ZIP level.
- Corrupt/encrypted/unsupported archives fail clearly.
- Integrity checks, hidden metadata filtering, normalized paths, and folder-safe identities must remain.
- No extraction to arbitrary filesystem paths.

Engine:
buildNetworkFromLayers(layers, options, runtime?) -> Promise<{network, issues, summary}>

NetworkLayer includes:
id, name, role, features, mapping, defaults, units, customAttributes, filters, rules.

NetworkBuildOptions includes:
units, headlossFormula, snapTolerance, splitAtIntersections,
splitAtVertices, removeDuplicatePipes, keepLargestComponent,
junctionDefaults, labelPrefixes.

Engine progress uses:
{stage: attributes|topology|devices|complete, completed, total}.

Prepared model:
prepareGisModel(layers, options, metadata, configuration)
-> {model: BuildModelResult, report: GisBuildResult, name}.

Shared types:
GisBuildMetadata: name, flowUnit, unitSystem, fetchElevations?, signal?.
GisBuildProgress: stage, progress, completedStages?.
GisBuildResult: assetCount, issues, summary, stages?.
Pipeline progress is a FRACTION from 0 to 1.
The UI converts that fraction to a 0-to-100 percentage.
Do not recreate the earlier fraction/percentage mismatch.

Command:
useBuildGisModel() -> {build, openModel}.

Safe lifecycle:
- Opening the native builder preserves the active project.
- Building prepares another model without replacing the active project.
- Every new build clears the previous prepared result.
- Recheck AbortSignal after prepareGisModel resolves.
- A generation counter rejects an older preparation that resolves after a newer build.
- Only Open model, after the normal unsaved-changes continuation, starts replacement.
- Block interaction with the existing loading dialog while the final commit runs.
- Start the new project through existing persistence.
- Persist custom attribute definitions separately as required by the existing converter integration.
- After successful startup, fit bounds, clear old INP/project file associations, mark unsaved, emit completion tracking, and open Network Review.
- Failed startup must not mark the old file unsaved or pretend import succeeded.
- Preserve late-cancellation, failed-startup, and stale-result regression tests.
